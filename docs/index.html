Where these numbers come from (every figure is reproducible from reports/*):

  • ≈ 0.57 (Model A). Leave-one-creator-out ROC-AUC for the within-creator breakout target is 0.55–0.58 across model families — best pre-publication model 0.569 (logistic) / 0.581 (gradient boosting); the deployed Model A is 0.568. Optuna tuning and stacking add under 0.01, so the wall is the available information, not the model.
  • ≈ 0.75 (Model B). Adding only first-day engagement lifts ROC-AUC to 0.750 (95% CI [0.745, 0.756], temporal test). Leak-free: it uses day-1 signals only, and the success label is measured strictly after that, so the model cannot see its own outcome.
  • 16 / 16 methods. Sixteen alternatives — boosting, deep nets, learning-to-rank, multi-task, causal IPS, clustering, a rule-based scorer, an FT-Transformer — all score at or below the 0.567 best-Model-A baseline (best alternative 0.563). Three more (QDA, TabPFN-v2, TabNet) could not fit and are reported as skipped, not hidden.
  • 0.51 vs 0.86 (fame-leak). A model that sees only the creator's audience size reproduces the within-creator label at AUC 0.51 (≈ chance → the label measures content, not fame), but reproduces a naive absolute-views label at 0.86 (→ that label mostly measures fame). This is why the within-creator "beats your own median" target is used throughout.

What it is

A two-model triage on lingbow/tiktok-video-engagement-200k (209k videos, 1,872 creators) returning Post / Unsure / Do not post with the main factors and an explicit note on what a model can and cannot know. The honest finding: pre-publication reach is information-bound, not model-bound — so the product's value is triage + abstention + the day-1 amplify/cut decision, not a pre-publication oracle. Full method, ablations, literature grounding and limits are in the results notebook.

The data journey — the first real decision

The brief shipped datahiveai/Tiktok-Videos. EDA showed it cannot answer a pre-publication question: only 4 creators / 2,060 rows, a single engagement snapshot (no day-by-day → no day-1 signal and no horizon label), a dead repost_count column, and garbage timestamps — its deployed model scores ROC-AUC 0.52 (≈ random). So the first deliverable was choosing a proper dataset of record:

In lingbow, creator identity alone explains 74% of the variance in log-views — so an absolute-view label would grade fame, not content. That single fact forces the within-creator "beats your own median" target used throughout. Full EDA, dataset selection and the external sets that could raise the ceiling (SnapUGC, MicroLens, KuaiRand) are in the notebook.

This runs two real trained logistic models client-side (no server). The full Model A uses text embeddings and video-derived features that cannot run in a static page, so this is an honest caption-plus-metadata surrogate: held-out ROC-AUC … for Model A (pre-publication) and … for Model B once you add day-1 plays and likes. The full models and the analysis are in the notebook.

Why so few inputs: we measured feature impact (forward-addition and drop-column on a held-out set). Among pre-publication signals only topic moves the needle (about +0.013 AUC); caption wording, posting time, duration and flags add essentially nothing, so exposing more would be fake precision. The accurate, business-usable signal is the first day (Model B, AUC ≈ 0.71): post organically, enter day-1 plays, then decide whether to amplify. The full feature-impact study is in the notebook (section 10.2).
